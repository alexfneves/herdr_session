# Code Review — herdr-session, plan vs implementation

**Reviewed:** `b9f5d4b` — full implementation (src/, nix/, dev/, README) against `docs/requirements.md`,
`plan.md` (D1–D14, ISC-1..21, ISC-A-1..9) and `50-requirement-changes.md` (RCH-1, RCH-2/O11-O13).
**Verdict:** READY WITH CAVEATS — one P1 correctness bug, plus two test-integrity holes that must be closed
before this is trusted as "green".

All findings below were reproduced or re-derived in this review; nothing is taken from prior reports.

---

## P0 — none

No security hole with a working exploit, no auth bypass, no secret exposure. (Device strings into `ssh`
argv is the closest call — see P2-7, where the RCE path is *blocked* by OpenSSH 10.5 hostname validation
but option injection still happens.)

## P1 — fix before this is called done

### 1. `post_detach` ignores the device: cleanup on a REMOTE session stops/deletes LOCALHOST

**File:** `src/app/exec.odin:181`, `:237`, `:314-326`

`do_launch`/`do_attach` call `post_detach(cmd.name, we_created)` with a name only — the device is
dropped. `post_detach` then runs, unqualified:

```odin
run_capture(stop_argv(name), CAPTURE_TIMEOUT)      // "herdr session stop --json <name>"  ← HERE
run_capture(delete_argv(name), CAPTURE_TIMEOUT)    // "herdr session delete --json <name>" ← HERE
```

Those are **local** commands. For a remote session the app must use `control_argv(device, …)` (its own
ssh wrapper) — exactly what `control_argv`'s comment says this is for:

> "Without this the identity rule breaks in the worst available way: a delete on a REMOTE row would run
> `herdr session delete <name>` HERE and destroy a same-named LOCAL session."

The launch/attach paths honour that rule everywhere else (`do_delete` → `control_argv`); the detach path
does not.

**Reachability.** Not under the shipped default (`never`). It becomes live the moment the user sets
`cleanup_policy = "always"` or `"only_created"` — and **`README.md` explicitly recommends that value**
("If you want the old behaviour back, set `"cleanup_policy": "always"`"). With `always`:

- detach from a remote session → local `stop`+`delete` of that name;
- if a *same-named local* session exists (the entire `(device,name)` identity model exists precisely
  because "two boxes can each own `api`") → **the local session is destroyed**;
- the intended remote session keeps running, while the notice says it was "stopped and deleted".

**Test coverage:** none of it. `app_cases.odin:755-767` exercises only the pure predicate
`cleanup_should_run`, and `theme_cases` only the config round-trip. The code comment "the seam is
exercised on every detach" means the *boolean* runs — the *effect* (which host) is untested.

**Fix:** thread the device through and route through the existing wrapper:

```odin
post_detach :: proc(device: string, name: string, we_created: bool) -> string {
	if !cleanup_should_run(cleanup_policy(), name, we_created) { … }
	if is_local_device(device) {
		run_capture(stop_argv(name), CAPTURE_TIMEOUT)
		run_capture(delete_argv(name), CAPTURE_TIMEOUT)
	} else if is_remote_reachable(device) {              // or unconditionally:
		run_capture(control_argv(device, stop_argv(name)), CAPTURE_TIMEOUT)
		run_capture(control_argv(device, delete_argv(name)), CAPTURE_TIMEOUT)
	}
}
```
Until that is done, refuse non-local cleanup outright (`return "… left running (cleanup is local-only)"`)
rather than deleting the wrong machine's session. Add a test that asserts the argv *carries the device*
for a remote cleanup — the same shape as `attach_target_argv`'s proof.

## P2 — real problems, fix or explicitly accept

### 2. `dev/handoff-smoke.sh` always exits 0, even with failures

**File:** `dev/handoff-smoke.sh` (ends at the `#### TOTAL` printf; no `exit`)

Reproduced with a manufactured always-failing binary:

```
BIN=/tmp/fake-hs ./dev/handoff-smoke.sh /tmp/hs-fake-out
    #### TOTAL: 2 PASS / 10 FAIL
    exit code = 0
```

Every other suite gates correctly (`app/state/ui/theme/render/tui-smoke` all returned `1` under the same
fake binary). The `stty before == after` check in sections 2–6 is only *printed*, never counted, and
`verdict()` adds `0+0` for a section that produced nothing. ISC-9/ISC-10's evidence therefore has no
enforcement behind it.

**Fix:** `[ "$FAIL_TOTAL" -eq 0 ] || exit 1` at the end, and make `run_pty`/`verdict` use the house
`tally` rule from `app-smoke.sh:96-105` (0 PASS and 0 FAIL ⇒ FAIL).

### 3. Zero-assertion runs score as PASS (the known resize case — it is systemic, not isolated)

**Files:** `dev/resize-smoke.sh:50`, `dev/tui-smoke.sh:95` and `:120`, `dev/device_discriminator.py:59-61`

Confirmed the reported case:

```
$ BIN=/tmp/hs-local python3 dev/resize_drive.py selection-shrink
    SKIPPED — needs the fixture …
-- resize selection-shrink -> 0 PASS / 0 FAIL
rc=0        → wrapper prints "PASS selection-shrink (0 checks)"
```

Same arithmetic in `tui-smoke.sh::run_scenario` — the driver's `rc` is printed but **never gated**, and
`PASS_TOTAL/FAIL_TOTAL` only ever *accumulate*; a scenario that crashes with a traceback and no
`[PASS]/[FAIL]` lines contributes nothing. `device_discriminator.py` also `return 0`s when unarmed
(it is only saved by `app-smoke.sh` guarding the call site).

This repo already solved this properly in `app-smoke.sh`/`state-smoke.sh`:

> "A log with zero [PASS] lines is a FAILURE, not a pass."

**Fix:** lift that `tally` into a shared `dev/lib.sh` and use it in `resize-smoke.sh`, `tui-smoke.sh`
and `handoff-smoke.sh`; in `resize_drive.py`, make a skipped scenario record a failed/absent result
rather than returning with an empty ledger.

### 4. The model is only refreshed by the app's own mutations — the attach/delete guards run on stale data

**Files:** `src/main.odin:533` (`if eff.refresh { tui_refresh() }` — the only call site)

Nothing else refreshes: no periodic refresh, no refresh key. The list updates only after a launch or a
delete. Consequences:

- A session created/stopped/deleted in another terminal never appears, changes or disappears while the
  TUI is open. The `running` column silently rots.
- **The attach guard weakens with age.** `attach_guard` tests `is_known_session(rows, device, name)` —
  *membership*, not `running`. If the session was removed elsewhere after the last fetch, the stale row
  still passes, and `herdr session attach` is create-or-attach, so the app **creates** a fresh empty
  session under that name — the exact orphan class ISC-17 exists to prevent, reintroduced by staleness.
- `exec.odin`'s own comment promises otherwise: "*`rows` must be the freshest view of the world* … the
  poll loop passes its live table rather than a snapshot taken at startup". The live table is not fresh;
  it is *unrefreshed*.

**Fix:** refresh on entering `{Attach}` and `{Delete}` (local is ~3 ms; the remote fan-out is
non-blocking and merges when it lands), and/or add a refresh key and show the list's age in the footer so
"stopped elsewhere" is not invisible. At minimum, make `attach_guard` require `running == true` for a
local attach, so a stale row cannot authorise a create.

### 5. Delete freezes the UI for up to ~10–20 s (sequential blocking `run_capture` in the event loop)

**Files:** `src/app/herdr.odin:753-757` (`stop` then `delete`), `CAPTURE_TIMEOUT :: 10 * time.Second` at `:210`,
`src/app/exec.odin::do_delete` → `src/main.odin::tui_run_command` (inline in the poll loop)

A delete runs `stop` then `delete`, each a blocking `run_capture` with a 10 s budget, inside the
keyboard loop. Measured against the black-hole host:

```
$ time ssh -T -o BatchMode=yes -o ConnectTimeout=5 192.0.2.201 'herdr session delete --json nope'
real 0m5,014s
```

So: a row whose host went away between listing and acting ⇒ **two × 5 s = ~10 s of dead terminal**
(no key response, no repaint, no "working…" indication), and up to 20 s if ssh itself wedges.
Note `CAPTURE_TIMEOUT` (10 s) is deliberately larger than `ConnectTimeout` (5 s), so the app can wait
twice as long as the network bound it advertises (ISC-14).

**Fix:** pass a per-command budget tied to the ssh bound (e.g. 6 s) for control commands, set a
"working…" notice *before* the call and repaint, and ideally run control commands through the existing
fetch registry so the loop keeps servicing keys.

### 6. `registry_reap_debts` can never repay a reap debt (dead safety net)

**File:** `src/app/fetch.odin:349-350` vs `:536-541`

```odin
fetch_reap :: proc(f: ^Fetch) -> bool {
	if !f.spawned || f.settled { return f.settled }      // ← short-circuits on settled
…
registry_reap_debts :: proc(r: ^Registry) {
	for f in r.items {
		if !f.spawned || f.reaped { continue }           // ← selects settled && !reaped
		if fetch_reap(f) { continue }                    // ← returns true, never calls waitpid
	}
```

Every row that `registry_reap_debts` selects is immediately returned by `fetch_reap`'s `f.settled`
guard **without a `waitpid`**, and the caller treats that `true` as "collected". So the retry mechanism
documented in `kill_and_reap` ("left marked un-reaped so `registry_reap_debts` keeps trying") never
tries, and `registry_free`'s eight final sweeps are equally no-ops.

Producer: only `kill_and_reap`'s 250 ms budget expiry (`:527`), so it is rare — and the impact is
bounded because children are reparented at our exit. But the safety net is genuinely non-functional.

**Fix:** `if !f.spawned || (f.settled && f.reaped) { return f.settled }` in `fetch_reap`, and add a
test that constructs settled-but-unreaped and asserts `registry_unreaped` drains (it is currently only
defined at `:548` and asserted nowhere — the live suite checks `/proc`, which is the right *outcome*
check but doesn't exercise the retry).

### 7. A config/registry device beginning with `-` is accepted and injected as ssh options

**File:** `src/app/remotes.odin:90-97` (`remote_is_valid` rejects only empty/space/tab/newline/NUL)

`remote_list_argv`/`control_argv` place the verbatim device immediately after our options, so a device
like `-oProxyCommand=…` or `-F/tmp/evil` is parsed by ssh as an **option**, not a host. Measured with
OpenSSH 10.5p1:

```
$ ssh -T -o BatchMode=yes -o ConnectTimeout=5 "-F/tmp/evil_ssh_config" 'herdr session list --json'
hostname contains invalid characters          ssh_exit=255
```

**RCE is blocked here only incidentally:** after the option is consumed, the only remaining operand is
our fixed command string, which ssh rejects as a hostname before it ever connects. What *is* real:
silently overridden `BatchMode`/`ConnectTimeout`/`StrictHostKeyChecking`, an arbitrary ssh config file
read, and a fetch that reports `unreachable` for reasons the user cannot see. `launch_argv` has the same
shape into `herdr --remote <device>`.

**Fix:** reject a device whose first byte is `-` in `remote_is_valid` (with a warning), and/or emit
`--` before the host in the ssh argv. One line, and it removes the class rather than the instance.

## P3 — worth knowing, cheap to fix

1. **Three assertions that cannot fail.**
   `src/app_live.odin:472` — `check("the gate reads the installed herdr without bricking on it", true, …)`;
   `src/fetch_live.odin:491` — `check("healthy host has rows", true, …)` (label promises rows; the
   surrounding checks do assert them, so the *label* is the harm: `grep "healthy host has rows"` reads
   like coverage that isn't there);
   `src/app_live.odin:411` — `kind != .herdr_error || !outcome_needs_terminal(kind)` is a tautology
   (`outcome_needs_terminal` is never true for `.herdr_error`). Replace with assertions on the observed
   shape, or delete.
2. **`eintr-safe` doesn't test what its comment claims.** `dev/resize_drive.py` — the comment says a loop
   that stopped reading input "would pass the check above and still be dead", but the follow-up check is
   `not p.alive() is False`, i.e. aliveness again. Assert the screen changed after the Down keypress.
3. **`device_discriminator.py` docstring promises a check it does not make** ("the footer's attach
   preview carries the selected row's device verbatim" — explicitly not asserted here, moved to
   `app-live`), and its footer check `"attach" in footer` is near-always-true (the mode-selection key
   hint contains it regardless of any selection).
4. **README inaccuracies.**
   - The sample screen lists a row named `default`. `default` is never listed (D12/ISC-18; enforced in
     `model.odin:parse_session_list`). Contradicts a hard rule.
   - "The footer reports where the list came from" — **not implemented**: `machine_source_label` and
     `Discovery.source`/`note` are referenced only from tests, never from `main.odin`. This was also the
     plan's mitigation for the 0.8.2/0.9.x drift risk ("surface which path was taken in a debug line in
     the footer") — that seam never got filled.
   - "License MIT" vs `nix/package.nix` `license = lib.licenses.asl20`; and the Clay link
     (`github.com/nicbclay/clay-odin`) is broken.
   - "Every suite … proves the herdr session list is byte-identical after the run" — only
     `app`/`state`/`tui` do.
   - `herdr attach` → the actual command is `herdr session attach`.
5. **Missing-herdr message is wrong at boot.** `fetch.odin::local_snapshot` sets
   `"local herdr answered, but not with a session list"` even when `run_capture` never spawned anything
   (`spawned=false`, `.not_found`). The plan's edge case wanted `{Error}: "herdr not found on PATH"`.
   The app doesn't enter `{Error}` at boot; the footer just shows `local failed 0` with a message that
   accuses herdr of answering badly.
6. **`u16(ch)` truncation in the keymap** (`src/input/keymap.odin:120-122`) aliases astral runes into
   termbox's private range (`0xffff-N`). A Plane-1 scalar whose low 16 bits equal `KEY_ARROW_UP`
   (`0xffed`) would move the selection instead of filtering. Guard with `if ch <= 0xffff` before
   `map_code(u16(ch))`.
7. **Flake pinning is uneven.** `clay` is pinned by rev; `termbox2` tracks `url = …/master` (branch).
   `flake.lock` records the rev so builds are reproducible, but `nix flake update` moves termbox2 and
   the README's "The Nix build is fully pinned" overstates it. Pin the rev.
8. **Speculative generality in the registry parser** (given "MVP + targeted hardening"): `Raw_Machine`
   accepts five device spellings plus string/integer boolean tolerances (`"false"`, `"0"`, `"off"`) for a
   registry that has never been observed non-empty on this box; `Raw_Machine_List` is dead code kept "as
   documentation"; `registry_has_device` re-parses the whole payload once per merged entry (O(n²)
   json). Harmless at hand-sized lists; drop or simplify.
9. **`kill_and_reap` can hold the UI thread 250 ms** on the deadline path (`time.sleep(1ms)` loop,
   `fetch.odin:520-528`). Bounded and documented; noting it because it is the only non-trivial blocking
   besides finding 5.
10. **`fetch_close` uses fd `0` as the "closed" sentinel** (`fetch.odin:160-167`). If a pipe read end
    ever lands on 0 it would never be closed. Use `-1`.
11. **`write_doc` breaks its own atomicity claim.** `config.odin:466-470` does `remove(path)` then
    `rename(tmp, path)`. POSIX `rename` already replaces atomically; the remove opens a window where a
    crash loses the config entirely — exactly what the comment says the temp-file dance prevents. Drop the
    `remove`.
12. **Diagnostics never reach the user.** `Device.detail` (the `why` per host: permission denied,
    timed out, not-a-session-list) is written but never rendered — the footer shows only the status word.
    And at ≤120 columns `keys_line` drops whole hints, so `t theme` and `esc quit` disappear from the
    mode-selection footer — while the requirement says the footer shows *all* usable keys (their own test
    pty is 120 cols).

## D. Version-drift handling (RCH-2) — genuinely version-tolerant, not re-pinned

- **O12 is real.** `outcome()` keys on **stderr shape, not exit code**: envelope first (→ `.herdr_error`),
  then `TTY_REFUSAL_MARKERS` (→ `.tty_unavailable`), then `101` (→ `.tty_panic`); `outcome_needs_terminal`
  returns true for **both** generations. `unit_tty_version_tolerance` asserts the 0.8.2 capture *and* the
  0.9.5 capture produce the same verdict. It did not move the expectation to match this box — it widened
  the acceptance set and tests both members.
- **O13 is real and dedup'd.** `discover_resolved` unions registry ∪ config, dedup on the lowercased
  verbatim device, never returns "registry said X ⇒ ¬X"; tested for `[]`+config, bare-array+config,
  registry-only, config-only — and against the **live** `machine list` payload in `app_live:484-489`
  with the invariant `len(remotes) == from_registry + from_config`.
- **O11 guards are on production paths, not just tests.** `execute()` calls `attach_guard`/`delete_guard`
  unconditionally on the only path from the state machine to a spawn; `delete_session` and
  `launch_argv`/`attach_argv` re-check independently; `guard-attach`/`guard-delete` probe the real
  guards with a `waitpid(-1,WNOHANG)==ECHILD` proof that nothing forked.
- Caveats: the TTY-marker match is English-phrase based, so a future herdr rewording degrades to
  `.herdr_error` (still shown, not silent) — acceptable. `registry_has_device` re-parses per entry (P3-8).

## E. Concurrency / fd hygiene — sound

- `tui_wait` appends **both** `tb_get_fds()` descriptors (tty + resize self-pipe) plus
  `registry_fds(...)`, with the poll timeout capped at `POLL_SLICE` while anything is in flight (so an
  EOF-but-not-yet-reaped child cannot stall the loop for the whole deadline). `resize-no-key` proves the
  resize fd is really in the set behaviourally.
- Non-blocking read ends, drain-to-EAGAIN, `WNOHANG` reaping, `FD_CLOEXEC` applied to fetch pipes at
  fan-out (`cloak_fetch`) so nothing leaks into a long-lived `herdr` child; `fetch_kill` is SIGKILL and
  is followed by a reap; `fetch-live` asserts fd before/after across an 8-child mixed fan-out
  (hangs + errors + real ssh), zombies via `/proc`, and idempotent close.
- **One defect:** the *retry* reap path is non-functional (P2-6).
- No threads anywhere; confirmed by `/proc` signal posture and the suite's thread-count check.

## F. Handoff — meets the spec, one small mismatch

Verified in `terminal/handoff.odin`: `tb_shutdown()` → `fork` (no `setsid`, same fg pgroup, explicit
`chdir`) → `SIGINT`/`SIGQUIT` blocked before the fork and explicitly **unblocked in the child** (so the
child isn't born with Ctrl-C disabled) → `waitpid` looping on EINTR → `tb_init` + truecolor + hide-cursor
+ `tb_invalidate` + forced repaint via the installed hook. The env scrub drops the whole `HERDR_*`
namespace and keeps `TERM`/`COLORTERM`; `resolve_program` searches PATH in the parent so `execvp`'s
inherited-env search can't undo the scrub. `handoff-smoke` sections 4/5/6 prove exit propagation, scrub,
pgid/cwd and group-SIGINT delivery.

Gap: `run_child` turns a failed re-acquire into `.refused`, whose comment says "the caller exits" — but
`tui_run_command` maps `.refused` to `to_error()` only. In practice the next `tb_get_fds()` fails and
`tui_lost_terminal()` ends the run, so the behaviour is graceful; the comment is wrong. The signal
handler is not async-signal-safe (`tb_shutdown` in a handler) — acknowledged in-code, and the alternative
is worse. Observed live posture: `SigCgt = SIGTERM|SIGWINCH`, `SigIgn = SIGPIPE`, `ISIG` off (so `0x03`
is data, uniform across all states).

## A. Requirements walk — no missing feature found

List / create (unnamed + named, local + remote) / attach / delete (stop-then-delete, device-routed for
remotes via `control_argv`), parallel remote fetch with per-host status, live merge with identity-preserving
selection, four content modes, `local`-first then device then timestamp sort, filter starts empty, scroll,
theme picker pre-selecting the applied theme with persistence, `{Error}` state, corrupt-config tolerance,
`default` filtered at the parse boundary, "terminal too small" recovery, `Ctrl+C`/`Esc` from everywhere,
`nix run .` as a bare TTY-gated TUI (verified: `exit=3` with the sentence off a tty; verified the real
frame on a pty: no outer border, header/dividers/footer, four columns, live filter line).

Divergences worth naming: (a) a non-zero child exit lands as a footer *notice*, not the `{Error}` pane the
requirements sketch for "failed to create the remote session"; (b) the `~/.config/herdr_session.toml`
filename became `.json` — explicitly ratified by D13 and documented; (c) the footer cannot show all keys
at ≤120 cols (P3-12).

## Fixture removability — essentially true

Zero loopback addresses in `src/`. The fixture enters the product through **`tui_fixture_remotes`**
(`main.odin:419-436`) plus its one consuming loop in `tui_config_remotes`, plus one usage string;
everything else lives in `dev/` (and `nix/package.nix` ships only `src/` and `vendor/`, so none of it
is packaged). Two edits in `main.odin` + `rm -r dev/` = gone, product intact. Not literally "one
action", but close enough that no archaeology is required.

## D2 risk surfacing — good

`cleanup_policy = "never"` gets a prominent README callout block, the config-schema table, the
invariants list (`default` never destroyed; unknown value ⇒ `never` + warning), and a "read this before
switching" pointer in the home-manager replacement section. The residual problem is the *inverse* risk:
the README tells users `always` restores `herdr-cycle`, without noting P1.

## What's genuinely good

- **The choke-point design actually holds.** One spawn path for `herdr`, one place that decides the
  stdout/stderr split, one guard layer, one argv-per-device rule — and the anti-criteria greps
  mechanically enforce "there is only one". This is why the hard rules survive at all.
- **The stream rule is structural, not a habit.** `outcome()` is the only function that picks a stream;
  `Drain_Stat`'s tri-state exists because the bool version was a 100 %-CPU spin waiting to happen, and
  the reason is written down where someone will read it before "simplifying" it back.
- **Identity (device,name) is carried everywhere it needs to be** — merge, selection across a merge,
  delete pre-check, name-collision checks per device, the two-alias discriminator.
- **O12/O13 are the right answer to environment drift**: widen acceptance and test both members, move
  the assertion from the hazard to the guard, read the baseline live instead of recalling it from a plan.
- **Honest harness culture.** `app-smoke.sh`'s "0 PASS = FAIL" rule, the `%!` printf-fallout gate, the
  live before/after session-list teardown proof, and tests that *report* what upstream did instead of
  asserting on it — these are unusually disciplined.
- **Verified handoff engineering.** Step-by-step mapping to termbox2 source lines, the ECHILD "we spawned
  nothing" proof, child-side env/pgid probes.
- **Config discipline:** read-modify-write that preserves foreign keys, atomic temp-file rename, JSON5
  tolerance, `make(json.Object)` traps documented, and every failure degrading to defaults **plus a
  visible warning** rather than a brick.
- Idle CPU measured at literally 0 ticks; the no-threads claim survives contact with the process table.

## Verdict

**Ready with caveats.** Safe to use today at the shipped defaults (`cleanup_policy = "never"`).

**Gating items before calling this done:**

1. **P1** — `post_detach` must be device-aware (or refuse remote cleanup). It is a wrong-machine delete
   one config line away, and the README recommends that line.
2. **P2-2 / P2-3** — close the zero-assertion / always-exit-0 scoring in `handoff-smoke.sh`,
   `resize-smoke.sh` and `tui-smoke.sh` using the `tally` rule this repo already invented. Until then the
   ISC evidence behind the terminal-restore and resize criteria is not machine-enforced.
3. **P2-4** — decide the refresh policy. Without it, ISC-17's guarantee degrades with the age of the
   list, and "stopped elsewhere" is invisible.

Everything else is polish; none of it blocks daily use.
